# ambox (Linux)

Linux-приложение на PySide6 для подключения VPN по NekoBox/sing-box конфигам.

## Как пользоваться выбором приложений (новый интерфейс)

На вкладке **VPN** нажмите **«Маршрутизация приложений · Настроить»**. Здесь три понятных режима:

- **Обычно** — действуют обычные правила доменов и DNS из настроек.
- **Только выбранные** — только выбранные приложения идут через VPN; остальной трафик идёт напрямую.
- **Кроме выбранных** — выбранные приложения идут напрямую, остальные через VPN.

Достаточно поставить галочку на программе: при первом выборе Ambox автоматически включает «Только выбранные». В списке используются **имя и иконка из `.desktop`-файлов Linux** (XDG_DATA_HOME / XDG_DATA_DIRS), а соответствие маршрутизации определяется **путём реально исполняемого файла**, а не названием окна. Доступны поиск, фильтры **«Все / Запущенные / Выбранные»**, кнопка обновления и ручной выбор исполняемого файла **«+ Файл»**. Даже закрытые приложения остаются выбранными после перезапуска.

**Особенности Linux:** приложения Flatpak, Snap и обёртки могут запускать отдельные сетевые процессы. Если приложение не видно или его трафик не определяется, запустите его и откройте фильтр «Запущенные» либо добавьте фактический исполняемый файл. В режиме «Только выбранные» системный DNS намеренно работает напрямую: DNS от общего системного резолвера нельзя достоверно отнести к конкретному приложению. Режимы приложения не являются Kill Switch или гарантией отсутствия утечек; поведение зависит от поддержки определения процессов в sing-box/TUN. Доменные правила не могут заставить другие приложения использовать VPN в режиме «Только выбранные».

**Дизайн:** единая тема вместо накопленных перекрывающихся Qt-стилей, компактные карточки, один основной CTA и три главных раздела. Маршрутизация приложений теперь доступна с главного экрана.

## Что нового в обновлении

- **Компактный интерфейс:** окно 540×720 по умолчанию, основные вкладки «VPN», «Конфиги», «Подписки», дополнительные возможности — в меню «Ещё». Без широкой боковой панели и дублирующих кнопок.
- **Понятная работа с источниками:** «Мои конфиги» (ручной импорт) и «Из подписок» (серверы подписок) — два отдельных режима. Кнопка «Серверы» из карточки подписки открывает ровно её узлы.
- **Smart Connect:** оценка качества узла по истории задержки, изменчивости RTT и доступности; защита от слишком частого переключения. Это не тест скорости VPN и не оценка пропускной способности.
- **Безопасное переключение профилей:** новый JSON проверяется командой `sing-box check -c ...` до остановки существующего процесса. При неудачном запуске нового профиля клиент пробует восстановить предыдущую конфигурацию. **Между перезапусками процесса кратковременный разрыв остаётся возможным.**
- **Восстановление соединения** после неожиданной остановки процесса: до 5 попыток с увеличением задержки (опционально).
- **График загрузки/отдачи** в реальном времени, избранные серверы и сортировка по качеству, быстрый выбор сервера через трей.
- **Диагностика по запросу:** статус TUN, DNS, публичный IP, задержка до проверочного ресурса, память процесса. При раздельной маршрутизации проверка может идти напрямую; это не тест защиты от утечек.
- **Маршрутизация:** настраиваемые пресеты, простой и экспертный режим, экспериментальный `auto_redirect` для Linux/nftables (только по явному включению).
- **Подписки:** отдельная страница с карточками, расходом/остатком трафика, сроком действия, датой обновления, индивидуальной кнопкой «Обновить» и действиями «⋯» (переименовать, изменить ссылку, автообновление, удалить). Обновление выполняется асинхронно; ошибка отображается рядом с подпиской. Новая ссылка сохраняется только после успешной загрузки серверов. Плановое обновление и уведомления о квоте сохранены.
- **Приватность:** файлы настроек и профилей создаются с правами `0600`, постоянные случайные идентификаторы вместо секретов в ключах статистики, скрытие известных типов секретов при копировании логов.

**Обязательно:** `sing-box 1.12.0+`, Python и зависимости из `requirements.txt`. После замены файлов рекомендуется сделать резервную копию `~/.ambox` и проверить версию `sing-box version`.

### Как пользоваться новой навигацией

1. **VPN:** подключение, переключение текущего сервера, качество и трафик.
2. **Конфиги → Мои конфиги:** ручной импорт из файла или буфера, экспорт и удаление своих конфигураций.
3. **Конфиги → Из подписок:** серверы из подписок с фильтром по поставщику. Нажмите на сервер дважды для подключения.
4. **Подписки:** добавление (Happ/HTTPS), ручное и массовое обновление, остаток трафика, изменение ссылки и переименование. Нажатие «Серверы» откроет связанные конфиги.
5. **Ещё:** маршрутизация, приложения, диагностика и логи. Все прежние экспертные возможности сохранены.

Обновление через GitHub после слияния PR: `git pull --ff-only origin main && ./build_linux.sh`. Перед первым запуском новой версии рекомендуется сделать резервную копию `~/.ambox`.

## Что умеет
- Импорт профилей из `sing-box` JSON, Xray/V2Ray JSON-конфигураций (включая массивы подписок), а также списка ссылок (`vless://`, `vmess://`, `trojan://`, `hysteria2://` / `hy2://`, `ss://`, `http://`, `https://`, `socks://`).
- Полная поддержка Happ-ссылок:
  - Незашифрованные: `happ://add/...`, `happ://import/...`, `happ://subscribe/...`, `happ://sub/...`, `happ://https://...`.
  - Зашифрованные ссылки Happ: `happ://crypt`, `happ://crypt2`, `happ://crypt3`, `happ://crypt4` и `happ://crypt5` со встроенной расшифровкой (RSA + ChaCha20-Poly1305).
  - Полные Xray-конфиги из Happ-подписок (например, HiroVPN) используются целиком: все узлы, балансировщики (→ `urltest`), правила маршрутизации по доменам/IP/портам, `geosite:`/`geoip:` (rule-set'ы MetaCubeX кешируются в `~/.ambox/rule-sets`).
  - Перед подключением узлы конфига проверяются; недоступные из текущей сети исключаются, и если основной сервер локации заблокирован, трафик идёт через резервные узлы той же подписки.
- Управление и обновление подписок:
  - Отдельная вкладка «Подписки» со встроенным небольшим диалогом добавления, поддержкой буфера обмена и deep link.
  - Обновление отдельных подписок и пакетное обновление всех (`Ctrl+U` или «Обновить все»).
  - Изменение URL не удаляет существующие узлы: ссылка заменяется только при успешном получении новых серверов.
  - Быстрый переход к серверам выбранной подписки, контекстное меню «⋯» для редких действий.
  - Атомарная замена устаревших узлов с сохранением активного подключения и статистики трафика.
  - Отображение информации о квоте трафика и дате окончания подписки из заголовка `Subscription-Userinfo`.
  - Опция автообновления подписок при запуске приложения.
- Автоматическое определение локаций и стран:
  - Определение стран по эмодзи-флагам, названиям стран/городов (на русском и английском), ISO-кодам и доменным суффиксам серверов.
  - Выпадающий список фильтрации по локациям (`🌍 All locations`, `🇩🇪 Germany`, `🇳🇱 Netherlands` и т.д.).
  - Сортировка по локации.
  - Отображение флагов стран в списке профилей и виджете активного профиля на вкладке VPN.
  - Автопереключение на лучший доступный узел независимо от открытого экрана и фильтра списка.
- Выбор профиля в интерфейсе.
- Подключение/отключение через локальный `sing-box`.
- Показ статуса и логов в окне.
- Авто-замер latency и отслеживание timeout.
- Статистика трафика по каждому профилю (накопительно), с сохранением между запусками.
- Автопереключение по истории качества соединения при включённом Smart Connect.
- Гибкая маршрутизация: весь трафик, только выбранные домены/IP, или весь трафик кроме выбранных доменов/IP.
- На главном экране есть переключатель **«Сайты .ru — всегда напрямую»**. Это глобальное исключение с наивысшим приоритетом: при включении известные доменные соединения `.ru` и их поддоменов идут напрямую в любом режиме приложений и маршрутизации; DNS-запросы `.ru` используют локальный `direct-dns` даже при выборе прокси/пользовательского DNS. Значение сохраняется при перезапуске, применяется к активному VPN с переподключением и не выключается при смене пресета.
- Опция включения поддоменов для доменных правил.
- Режимы DNS: проксировать DNS, не проксировать DNS, или использовать `Custom DNS server`.
- Для `Custom DNS` поддерживаются `IP/домен[:port]`, IPv6 в квадратных скобках или без них, `udp://...`, `tcp://...`; перед подключением сервер проверяется DNS-запросом.
- Выбор приложений в разделе «Ещё → Приложения» (и быстрый переход с VPN) позволяет включить VPN только для отмеченных программ или исключить отмеченные. Для программ с путём используется точное сопоставление исполняемого файла; для старых правил без пути доступно сопоставление по имени процесса.
- Флаг `-d` для debug-режима (подробные логи и traceback).

## Установка
```bash
cd /path/to/nekobox_gui_app
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt pyinstaller
```

## Важно про `sing-box`
Приложение запускает команду `sing-box run -c <config>`, поэтому `sing-box` должен быть установлен и доступен в `PATH`. Требуется sing-box **1.12.0+**: клиент откажется запускать несовместимую версию и проверит конфигурацию перед переключением.

Пример для Ubuntu:
```bash
sudo apt install sing-box
```

Для TUN обычно нужны права `CAP_NET_ADMIN`:
```bash
sudo setcap cap_net_admin+ep "$(command -v sing-box)"
```

## Сборка одного файла (ELF)
```bash
cd /path/to/nekobox_gui_app
./build_linux.sh
```

После сборки бинарник будет тут:
```bash
/path/to/nekobox_gui_app/dist/ambox-linux
```

## Запуск
Обычный режим:
```bash
/path/to/nekobox_gui_app/dist/ambox-linux
```

Debug режим:
```bash
/path/to/nekobox_gui_app/dist/ambox-linux -d
```

Запуск свёрнутым в трей (удобно для автозапуска):
```bash
/path/to/nekobox_gui_app/dist/ambox-linux --tray
```

Импорт Happ-ссылки при запуске:
```bash
/path/to/nekobox_gui_app/dist/ambox-linux 'happ://add/https://subscription.example/profile'
```

Второй запущенный экземпляр не создаёт новое окно: он передаёт ссылку (если есть) уже работающему приложению и завершается. После выхода из сна VPN-туннель проверяется и при необходимости переподключается автоматически.

Ярлык для меню приложений и автозапуска — `packaging/ambox.desktop` (путь в `Exec=` поправь под себя):
```bash
cp packaging/ambox.desktop ~/.local/share/applications/
update-desktop-database ~/.local/share/applications
# автозапуск при входе:
cp packaging/ambox.desktop ~/.config/autostart/
```

Данные приложения сохраняются в `~/.ambox`:
```bash
~/.ambox/settings.ini       # настройки интерфейса, routing, DNS, статистика
~/.ambox/profiles.json      # импортированные VPN-профили
~/.ambox/active-config.json # текущий config для sing-box
~/.ambox/cache.db           # cache sing-box
~/.ambox/app.log            # лог приложения
~/.ambox/imports/           # локальная папка для ручного импорта конфигов
```

## Как использовать
1. Нажми `Import file`.
2. Выбери файл с конфигом.
3. Или используй `Paste from clipboard` / `Ctrl+V`.
4. Поддерживаются ссылки: `vless://`, `vmess://`, `trojan://`, `ss://`, `http://user:pass@host:port#Name`, `socks://user:pass@host:port#Name`, а также `happ://add/https://...` для загрузки подписки.
5. Выбери режим `Routing`.
6. При режимах с выборочной маршрутизацией укажи домены, IP-адреса или CIDR-сети построчно и при необходимости включи `Include subdomains` для доменов.
7. Для крупных сервисов (Google/YouTube/OpenAI и т.д.) обычно нужно добавить несколько связанных доменов/CDN, а не только один основной домен.
8. При необходимости включи `Smart Connect` для выбора сервера по качеству.
9. Выбери `DNS mode`: через прокси, напрямую, или `Custom DNS server`.
10. Для `Custom DNS server` укажи адрес (например, `1.1.1.1`, `dns.google`, `udp://1.1.1.1:53`).
11. Укажи `Timeout` в миллисекундах.
12. При необходимости открой вкладку `Applications`, выбери режим и отметь приложения. Список можно обновить; уже сохранённые приложения остаются доступными даже когда они закрыты.
13. Нажми `Connect`.

### Приоритет маршрутизации приложений

Если включён режим приложений, правила применяются в таком порядке:

1. перехват DNS, локальные адреса и адреса серверов прокси обрабатываются отдельно;
2. **`.ru` (при включённом переключателе)** — всегда напрямую, до выбора приложения и правил провайдера;
3. правило выбранного приложения;
4. в обычном режиме — остальные правила доменов/IP и провайдера Xray/Happ;
5. общий маршрут профиля.

Для `.ru` также задаётся исключение в DNS-правилах, направляющее запросы в `direct-dns` независимо от выбранного DNS-режима. Это **не гарантирует обход VPN для абсолютно каждого соединения**: если клиент использует IP-адрес вместо имени, собственный зашифрованный DNS (DoH/DoT), ECH или имя не определяется через sniffing, сопоставление `.ru` невозможно. Настройка не является Kill Switch; DNS выбранного приложения не отделяется от общего системного DNS.

Изменения маршрутизации, DNS и выбора приложений сохраняются сразу. Если VPN уже подключён, приложение автоматически пересобирает и валидирует конфигурацию спустя примерно 650 мс после последнего изменения, затем переподключает активный профиль; GUI перезапускать не нужно. При невалидных настройках текущее соединение сохраняется. Во время успешного переключения возможна короткая пауза трафика.

Если видишь `sing-box not found`:
1. Установи `sing-box`, или
2. Нажми кнопку `Install sing-box` в приложении (используется `pkexec` + репозиторий SagerNet).

Если установка падает из-за `repository ... is not signed`:
1. Почини/отключи проблемный сторонний APT-репозиторий.
2. Повтори установку через кнопку `Install sing-box`.

## Ограничения текущей версии
- Endpoint RTT измеряется запросом/соединением к узлу и **не отражает** jitter пакетов, потери пакетов или скорость реального VPN-туннеля; Q-score — эвристика по истории RTT и доступности.
- Полноценный системный Kill Switch с ограниченным привилегированным сервисом **не реализован**. `auto_redirect` и `strict_route` его не заменяют. Защиту от утечек при аварийной остановке нужно отдельно проверять на конкретном Linux-дистрибутиве.
- Переход между профилями перезапускает процесс sing-box, поэтому краткий сетевой разрыв возможен даже после предварительной проверки и при успешном откате.
- Реальные интеграционные проверки требуют Linux, PySide6, sing-box и полномочий для TUN. Для проверки логики без Qt: `python -m pytest -q tests/test_enhancements.py tests/test_config_parser.py tests/test_latency.py tests/test_subscriptions_and_locations.py tests/test_net_session.py tests/test_xray_bundle.py tests/test_happ_hwid.py`.
- Публичный IP и DNS в диагностике могут проверяться вне туннеля при split-tunneling. Отчёт диагностики и копируемые логи автоматически скрывают известные форматы секретов, но перед отправкой третьим лицам их нужно просмотреть вручную.
- Обновление самого приложения и полная локализация интерфейса пока не реализованы; это отдельные функции будущего релиза.
